\section{Experimental Setup}
\label{sec:setup}

We run two studies. The first is a controlled simulation on four forecasting
tasks. The second repeats the core comparison on real quantum hardware. In both,
every aggregation choice reads the very same measurement record, so any
difference in accuracy comes only from how the shots are organized and not from
running the circuit differently.

\subsection{Simulation reservoir and setup}

The simulation reservoir is a fixed six-qubit circuit with two shallow data
reuploading layers~\cite{perezsalinas2020data}. Each layer applies
input-dependent $R_y$ and $R_z$ rotations with fixed per-qubit offsets,
neighboring $R_{zz}$ couplings, and fixed non-Clifford mixing rotations. All
angles are drawn once and then frozen; additional frozen circuits measure
sensitivity to that draw. Each computational-basis measurement provides six
local signals $Z_i$ and five neighboring correlations $Z_iZ_{i+1}$. A leaky
integrator with leak $0.2$ and the ten most recent steps provide temporal
memory, and ridge regression maps these features to the next value.

We forecast four time series one step ahead. Two are chaotic synthetic systems,
Mackey--Glass~\cite{mackey1977oscillation} and R\"ossler~\cite{rossler1976equation}.
Two are measured real-world series, the Santa Fe laser
intensity~\cite{gershenfeld1993future} and the monthly sunspot
number~\cite{sidc2026sunspots}. All four pass through this frozen circuit and
the identical processing pipeline, with the same features, memory, scaling,
model selection, and budgets.
The only thing that changes from task to task is the input sequence. This
isolates the effect of aggregation from any per-task tuning.

Every method reads the same raw record. Next to EV, Grouped, and Raw we include
three references that separate the aggregation effect from the quantum device.
Cov-EV adds a shot-covariance penalty to plain averaging, an ideal noise-free
version of the reservoir removes sampling noise entirely, and the classical
input processed in the same way removes the reservoir. To keep the statistics
honest, each synthetic task is run on five independently generated trajectories
and each real series on five separate time windows with disjoint test blocks.
Within each of these units we repeat the experiment over three circuit settings,
three measurement draws, and three random groupings, average those repeats, and
only then form paired confidence intervals across the five independent units.
Repeated simulations of one sequence are therefore never counted as independent
forecasting problems.

Model selection never touches the test data. After a short washout, the final
fifth of each series is set aside and left untouched while settings are chosen.
The earlier part is used in three expanding rounds that always fit on the past
and check on the block that follows, and only after the group size and ridge
strength are fixed is the reserved fifth scored once. Grouped predictions are
averaged back to one forecast per step, so every method is judged on the same
forecasts. The main budget places $20$ shots at each of $500$ time steps. Two
further ways of spending the same ten thousand executions, more shots with fewer
steps and fewer shots with more steps, serve as secondary analyses. All
reservoir parameters, data generators, window origins, and selection rules are
fixed and stored before any test block is seen.

\subsection{Hardware setup}
The hardware study deliberately uses a different reservoir. It is a fixed
ten-qubit circuit with one input qubit, nine memory qubits, a single ring of
entangling gates, and ten local outputs, mapped to selected qubits on the
\emph{ibm\_fez} and \emph{ibm\_marrakesh} processors and held fixed across all
four tasks. Its purpose is to check whether the same aggregation procedure still
helps on a second circuit and a different set of measured features. It is not a
hardware implementation of the six-qubit simulator and not a comparison of
qubit counts. As in
simulation, every method receives the same circuit outputs and only the
classical grouping of shots changes. For each task and processor we take one
acquisition of $400$ shots at each of $500$ time steps and split it into twenty
ordered, disjoint records of $20$ shots. The resulting intervals describe how
much the result varies among the measurement blocks of that single acquisition.
They do not stand in for independent devices or separate calibration periods.

The three simulation budgets are $(T,N)=(250,40)$, $(500,20)$, and
$(1000,10)$, each totaling 10,000 circuit executions. The supplement and
\ifdefined\ANON artifact\else
\href{https://github.com/eybmits/split-ensemble-qrc}{artifact}\fi\ provide the
splits, settings, outputs, hardware job IDs, checksums, and rebuild scripts.
